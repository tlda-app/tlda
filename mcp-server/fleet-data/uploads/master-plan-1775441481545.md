## Track E: Agents Panel + Search Usability

These exist but don't actually work as useful tools. Need a design pass before coding.

### E0. Agents panel usability
**What exists:** Shows who's alive. That's about it.
**What's broken/missing:**
- Can't spawn agents from the panel
- Can't respawn dead/stale agents from the panel
- Stale agents are made invisible — should be visible but folded/dimmed. Making things invisible AND folded is redundant and hides information.
- No actionable info per agent — can't see their task, can't see their last message, can't click to open their chat
**What's needed:** A design pass. Someone thinks through: what should each row show? What actions should be available? What does the stale/dead section look like? Write a plan with mockup/description BEFORE coding.
**Size:** Design first (small), then implementation (medium)
**Agent:** 1 opus — design only first, get Skip's approval, then implement

### E0b. Search usability + "everything Skip said" view
**What exists:** Search shape on canvas. Shows results with timestamps and agent names.
**What's broken:** No actual text content in results. No message body. Nothing actionable. You see who talked when but not what they said. Completely useless for finding information. And there's no way to see all of Skip's messages across all agent threads — they're scattered across 50+ threads with no aggregation.
**What's needed:**
- Search results show actual message text, not just timestamps
- Filterable by agent, time range, topic
- Clickable results (jump to that point in chat)
- A "me" / "Skip" filter that pulls messages from ALL threads — same chat UI, different data source. So "search for what Skip said about chips" just works.
- This also fixes the agent onboarding problem: new agents can read Skip's actual words on any topic before starting work.
**Backend fix needed:** `get_thread(agent="skip")` should aggregate across all agent threads, not just return the current session. This is a fleet server change.
**Size:** Design first (small), then implementation (medium-large — fleet server + search shape UI)
**Agent:** Can be same agent as E0

## ISSUE: Health monitoring didn't catch real failure

**What happened:** tlda went down while Skip was using it. Health dots (just merged today) didn't help — the server process died and restarted but the SPA was returning 404 (stale or missing bundle). Skip had to ask "tlda down?" twice before anyone noticed.

**What's needed beyond health dots:**
- `tlda doctor` should check: is the SPA actually serving pages (not just "is the port open")? Is the bundle current? Did a rebuild happen after the last merge?
- Health dots should detect "server up but SPA broken" — poll an actual page load, not just the API
- Auto-rebuild after merge (or at minimum, detect stale bundle and warn)
- When health goes red, don't just show a dot — surface it loudly (terminal card? chat message?)
