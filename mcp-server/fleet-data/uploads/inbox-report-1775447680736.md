## Test 4 — Sync schema (crash prevention)

**Issue discovered:** `fleet-tasks` and `fleet-inbox` were missing from `server/lib/sync-rooms.mjs`. Without schema entries, creating either shape triggers `INVALID_RECORD` sync error → React hooks count mismatch → full editor crash.

**Fix applied:** Added both entries to `sync-rooms.mjs`:
```js
'fleet-inbox': {
  props: { w: T.number, h: T.number },
  migrations: createMigrationSequence({ sequenceId: 'com.tldraw.shape.fleet-inbox', sequence: [] }),
},
```

**Verified:** Server restarted, shape placed, no crash, no console errors.

**PASS**

## Test 5 — Approve/Reject logic (code review)

Code path verified by inspection:

**Approve:**
```js
await fleetSendMessage(current.agent, `✓ Approved — ${current.description || 'task'}. Nice work.`)
dismiss(current.id)  // removes from visibleTasks, advances index
```

**Reject (with optional note):**
```js
const note = rejectNote.trim() || 'Please revise.'
await fleetSendMessage(current.agent, `✗ Not approved — ${current.description || 'task'}. ${note}`)
dismiss(current.id)
```

**Navigation:** ‹ › buttons move through `visibleTasks[currentIdx]`. `dismiss()` removes from a local `Set`, not from the server — this is intentional (no `acknowledged` flag write yet, by design).

**Card state cannot be live-tested:** No tasks currently have `reported: true`. Card state would show on first real `task_done()` call.

**PARTIAL** — logic verified by code review; live card state not exercised.

## Known issues / follow-up

1. **`acknowledged` flag not written on approve/reject.** Currently the shape just dismisses locally (session-level `Set`). After reload, dismissed cards reappear. The spec mentions a persistent `acknowledged` field — not yet wired to the server. Tracked as future work.

2. **Shape placed over document text** (test artifact). Playwright placed the shape at `y=600` which overlaps page 1. In real use, Skip places it in empty canvas space. Not a bug.

3. **CSS opacity:** Shape background appears semi-transparent in the worktree server build. May be a CSS variable resolution issue in the production bundle. Not reproducible as a blocking bug — needs live Safari check.
