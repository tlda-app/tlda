# What Skip's Environment Looks Like

> **Audience:** Every agent. Read this before your first task.

## The Short Version

Skip reviews papers and coordinates agents through **tlda** — a custom app that renders LaTeX as zoomable SVG pages on a TLDraw canvas. He views it in Chrome (occasionally on iPad with pen annotations). **He has RSI and cannot type.** Fleet chat via voice is his only communication channel.

Your tex output does not become a PDF. It becomes rendered SVG pages in an interactive canvas. Skip sees your work the way a reader sees a published paper — but with annotation tools layered on top.

## What Skip Sees

Everything lives on **one TLDraw canvas** — the paper, agent chat, agent management, all in one zoomable space. This is not three separate apps; it's one viewer.

### The Canvas Layout

It's one Chrome tab, one TLDraw canvas. Skip's typical layout:

```
┌────────────────────────────────────────────────────────────────────────┐
│  FLEET HUD (left margin)             │  DOCUMENT        │  PAPER INFO │
│                                      │                  │             │
│  ┌──────────┐ ┌──────┐ ┌──────┐     │ ┌──────────────┐ │  ┌───────┐  │
│  │ Agents  │ │ Chat │ │ Chat │     │ │  Page N      │ │  │  TOC  │  │
│  │ Panel   │ │ with │ │ with │     │ │  theorems    │ │  │       │  │
│  │         │ │ math │ │fleet │     │ │  proofs      │ │  │ notes │  │
│  │ Search  │ │ agent│ │agent │     │ │  equations   │ │  │       │  │
│  │ (below) │ │      │ │      │     │ │  figures     │ │  │       │  │
│  └──────────┘ └──────┘ └──────┘     │ ├──────────────┤ │  └───────┘  │
│                                      │ │  Page N+1    │ │             │
│  4 shapes in 3 columns              │ │  ...         │ │             │
│                                      │ └──────────────┘ │             │
├────────────────────────────────────────────────────────────────────────┤
│ [voice input bar]                                                      │
└────────────────────────────────────────────────────────────────────────┘
```

The layout has three zones:

- **Fleet HUD** (left margin) — 4 shapes in 3 columns:
  - Col 1: Agents panel (top) + search (bottom), stacked
  - Col 2: Chat with one agent (e.g. math agent)
  - Col 3: Chat with another agent (e.g. fleet/infra agent)
  
  Each chat column is a filtered view — Skip sees that agent's messages + his replies, with timestamps. Your `chat()` messages appear here with markdown rendering. **This is where Skip reads your work.**

- **Paper pages** (center) — SVG renders of your LaTeX, stacked vertically. Full math typesetting, clickable cross-references, figures with captions. This is the document being worked on.

- **Paper info** (right margin) — TOC with section links, sticky notes, reference material for the current document.

- **Voice input bar** (bottom) — Skip's voice transcription input. He speaks, it transcribes, he sends.

**The HUD and the paper are peers on the same canvas.** Skip can zoom out to see everything, zoom into a chat to read details, or zoom into the paper to review math. When doing both math and fleet work, one chat column typically has the math agent, the other has the fleet agent, and the paper is whatever the math agent is working on.

### The Paper Pages

Your LaTeX output renders as **SVG pages on the canvas** — not a PDF viewer, not Preview.app:
- Full mathematical typesetting (theorems, corollaries, remarks, display math)
- Clickable cross-references (equation numbers, proposition refs)
- Proper figure and table layout
- Page-by-page vertical stacking

**Figures and plots use SVG too.** The viewer only displays SVGs — not PNGs, not PDFs. If Skip says "I don't see a picture," it means the SVG is missing or broken. When saving plots, always use the `save_fig()` helper (see below) which saves all three formats.

When Skip reviews on iPad (occasionally), he sees these same pages with pen/annotation tools overlaid — circles, highlights, sticky notes with KaTeX math.

### Annotations
Pen strokes, highlights, sticky notes (with KaTeX math), arrows — all TLDraw shapes anchored to source lines in the tex file. When Skip draws a circle around something on page 3, that maps back to a specific line in your `.tex` file.

### Proof Reader
Press `r` to highlight proof regions and show theorem statements. Cross-page proofs show the statement in an overlay so Skip doesn't have to flip back.

### Plots: The Triple-Save Rule

The tlda viewer displays SVGs. The compiled paper uses PDFs. Agents need PNGs to visually verify their own work. **Always save plots in all three formats** using `save_fig()`:

```r
# Auto-loaded via ~/.Rprofile — no need to source() manually
# Source at: ~/work/lib/save-fig.R

save_fig(plot, "my-plot-name", width = 7, height = 3.5)
# Saves to figures/ by default:
#   figures/my-plot-name.png  — for you (the agent) to view and verify
#   figures/my-plot-name.svg  — for tlda viewer (what Skip sees)
#   figures/my-plot-name.pdf  — for compiled paper (LaTeX \includegraphics)

# Custom path:
save_fig(plot, "my-plot-name", width = 7, height = 3.5, path = "output/")
```

All three have matched dimensions so they look identical. `save_fig()` is auto-loaded in every R session via `.Rprofile` — just call it. If you only save a PDF, Skip won't see it in tlda. If you only save a PNG, the compiled paper won't have it. Always triple-save.

**The PNG is for you.** Read it before sharing. `save_fig()` gives you a PNG specifically so you can verify what the plot looks like before Skip sees it. Sharing an image you haven't looked at is asking Skip to be your eyes — that's not acceptable. Read the PNG, confirm it shows what you intend, then share or report.

## What This Means for Your Work

### Your LaTeX becomes SVG, not PDF
- `latexmk` compiles your `.tex` → DVI → `dvisvgm` converts to SVG per page
- The viewer loads these SVGs onto the TLDraw canvas
- Layout, spacing, figure placement, and page breaks all matter because Skip sees them rendered
- If your output looks bad as rendered pages, it looks bad to Skip

### Feedback comes through fleet chat and annotations
- Most feedback comes via fleet chat — voice-transcribed messages in the chat columns
- Occasionally, Skip annotates directly on the canvas: circles, underlines, arrows, highlights — these map to source lines via SyncTeX
- Sticky notes contain text (often with math via KaTeX)
- When you receive feedback via `wait_for_feedback` or `read_pen_annotations`, that's what annotation shapes contain

### Communication is fleet chat only
- Your chat messages appear **as a shape on the same canvas as the paper** — Skip reads them right next to the document
- **Never** put important messages in terminal output — Skip can see your terminal in the chat shape (bash commands are logged), but he can't interact with it
- **Never** ask Skip to type something — he has RSI and communicates via voice
- Use `chat()` for all communication. Format with markdown.
- Fleet chat is **accessibility-critical** — if it breaks, that's priority zero

### Chat vs. published docs — know when to use each

Fleet chat renders LaTeX (`$inline$` and `$$display$$`) and markdown. **Default to chat for math results, updates, and conversation.** Skip reads it right there in the chat column — no hand interaction needed.

**`tlda_scratch(file, title)`** publishes a markdown file as a **separate tlda document** — a heavyweight option for substantial reports:

```
Agent writes scratch/analysis.md
        ↓
Agent calls tlda_scratch("scratch/analysis.md", "Bias Analysis")
        ↓
  Creates a new tlda project → builds HTML → serves in the viewer
        ↓
  Skip can navigate to it as a separate document (like opening another paper)
```

This is heavyweight — it creates a whole other document, not a note on the current canvas. Use it for substantial reports that deserve their own page, not for quick results.

**When to use each:**

| | `chat()` | `tlda_scratch()` |
|---|---|---|
| **Math results, equations** | ✅ Default | Only if very long |
| **Status updates, questions** | ✅ Always | Never |
| **Screenshots, plots** | ✅ Include file path | Never |
| **Reports, analyses** | Short ones | ✅ Long/detailed ones |
| **Content Skip wants to keep** | Scrolls away in chat | ✅ Separate document |
| **Hand interaction required** | None | Navigate to new doc |

**Rule of thumb:** If Skip needs to read it once and respond, use `chat()`. If it's a substantial report that deserves its own document, use `tlda_scratch()`. Do not use `share()`.

### Edit the document directly
The tlda shadow repo saves every version of every document. **You can't permanently break things by editing tex files.** If an edit goes wrong, any prior version can be recovered. So don't write to `/tmp/` and ask Skip to review before applying — just make the edit. The watcher rebuilds, the viewer updates, and Skip sees the result immediately.

Shadow repo tools (MCP):
- `doc_version(doc)` — list recent versions (each build = a commit)
- `doc_checkout(doc, ref)` — revert to a specific version (hash or time like "20 minutes ago")
- `doc_diff(doc, ref1, ref2)` — diff between two versions

If you break something, `doc_checkout` gets it back. No need to be cautious.

### Sharing images in chat
Just mention file paths in your chat message — the fleet server auto-detects local paths, uploads images, and renders them inline:

```
chat("Here's the plot: /Users/skip/work/balancing-act/figures/plot.png")
```

The image renders inline in Skip's chat column. Rules:
- **Bare paths** → auto-detected, image rendered inline
- **Backtick-quoted paths** (`` `/path/to/file` ``) → treated as text, not embedded
- If the file doesn't exist, you get a warning
- No special tool needed — just `chat()` with the path in the message text

### Use tlda tools, not desktop apps
| Don't do this | Do this instead |
|---|---|
| `open file.pdf` | `tlda open <project>` |
| "Open it in Preview" | `tlda preview <project> [pages]` |
| "Check the PDF" | Take a playwright screenshot of the viewer |
| "I've updated the tex" | Push via `tlda push` or let the watcher pick it up |
| Put results in terminal | `chat()` via fleet |
| `open -a Safari ...` | `open -a "Google Chrome" ...` |

### The build pipeline
```
You edit .tex file
    ↓
tlda watcher detects change → pushes to server
    ↓
Server runs: latexmk → dvisvgm → synctex → proof-pairing
    ↓
Viewer reloads automatically (signal:reload via Yjs)
    ↓
Skip sees updated pages in the viewer
```

You don't need to run `latexmk` yourself. Edit the tex, and the pipeline handles the rest. If you need to check build status: `tlda status <project>`. If there are errors: `tlda errors <project>`.

### Verifying your own work
- `tlda preview <project> [page]` — renders a static preview of specific pages
- Playwright MCP tools — take screenshots of the live viewer
- **Never** tell Skip to "go check" or "reload and see" — verify it yourself first

## The Work Loop

The typical workflow:

1. Skip gives you a task via fleet chat (voice-transcribed)
2. You work on it — edit tex, write code, run analysis
3. You report progress and results via `chat()`
4. If Skip has the document open, changes rebuild and appear automatically
5. Skip reviews, gives feedback via chat (or occasionally pen annotations)
6. Repeat

For dedicated iPad review sessions (less common), the loop is tighter: Skip annotates → agent gets feedback via `wait_for_feedback` → agent edits → viewer reloads → Skip continues. But most of the time, communication happens through fleet chat.

Your job: do the work, verify it yourself, report results via chat — all without Skip having to explain anything twice or type anything.

## When Things Break

When Skip says "tlda is fucked" or "fleet is fucked" or "voice is broken" — this is an **emergency**. It means his communication channel is degraded or broken. **He has RSI and cannot type.** If the tools are broken, he's stuck.

### Emergency protocol
1. **Don't ask questions.** Skip may not be able to respond easily. Diagnose and fix.
2. **Run `tlda doctor`** immediately. It checks: server, fleet server, watchers, sync stores, build errors, MCP config. It auto-fixes what it can (restarts server, starts watchers).
3. **If `tlda doctor` doesn't fix it**, run `tlda doctor --fix` for more aggressive repairs.
4. **Check the specific thing that's broken:**
   - Voice not working → `tlda whisper status`, check the voice input bar
   - Fleet chat broken → check fleet server at `:5199`, check WebSocket connections
   - Document not updating → `tlda status <doc>`, `tlda errors <doc>`, check watcher
   - Viewer blank → check server logs (`tlda server log`), check browser console
5. **Fix it yourself.** Don't report the problem and wait for instructions. Don't ask Skip to type debug output. Investigate, fix, verify.

### Why this matters
Every minute the communication tools are broken is a minute Skip can't coordinate work, can't give feedback, can't do anything. The tools are his interface to the entire agent system. Fixing them is **always** higher priority than your current task.

## Voice Input and Transcription

Skip communicates via voice → Web Speech API transcription. His messages will contain:

### Transcription artifacts
- **"tilde," "Tilda," "Matilda," "till the," "tild"** → **tlda** (the app)
- **"five"** → **phi (φ)**; **"fat a"** → **theta (θ)**; **"I"** → possibly **phi** (stray pronoun)
- **"Asians"** → **agents**
- **"Cher"** → **share**
- Sound-alikes are common — interpret charitably in context

### Voice commands mixed into messages
Skip uses voice to navigate the UI. You may see words like **"left," "right," "send"** at the end of messages — these are voice commands for clicking buttons, not part of the message content. Ignore them.

### Chrome only
**Always use Chrome, never Safari.** Skip uses a foot cursor (accessibility device) that only works in Chrome. Voice input runs in Chrome. Fleet chat runs in Chrome. If you need to open a URL for Skip, use `open -a "Google Chrome" URL`. Safari tabs break his workflow.

### Voice stack
Currently **Web Speech API** (`SpeechRecognition`) in Chrome. No Whisper in production.
- Continuous mode with interim results
- Auto-restarts every 45s (Chrome) + 8s watchdog
- Voice commands: **"send"/"sent"** sends the message, **"right"/"left"/"next"/"other chat"** switches chat panels
- **Known issue:** Chrome Speech API poisons itself after extended use. When Skip says "voice dead — restart browser," that's what happened. An agent near a terminal should restart the browser.

Voice is in flux — a Whisper-based v10 exists in a worktree but isn't deployed yet.

### Viewer context in messages
When Skip sends a message from the fleet chat in the viewer, it carries metadata: `{ doc, page, camera, browser }` — which document is open, what pages are visible, and what browser he's using. So you can know what Skip is looking at when he sends a message.

### Browser console access
Use the fleet MCP tool `get_console()` to read Skip's browser JavaScript console. First call injects a collector, subsequent calls return buffered logs. Useful for debugging tlda viewer issues without asking Skip to check. Works with Chrome (primary) and Safari (fallback).

### General rule
If a message seems nonsensical, consider whether it's a voice transcription artifact before asking for clarification. Read it out loud — the intended word usually becomes obvious.
